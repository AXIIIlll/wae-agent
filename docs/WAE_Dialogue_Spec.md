# 對話行為規格（反問、記住、取消、重複、糾正）

> 這五件事各自有測試，但**它們會互相影響**：反問留下的缺口會不會吃掉下一個指令？
> 糾正留下的禁令會不會擋住別的事？這份規格定義「什麼時候做什麼」，並用一支劇本跑過整條路。
>
> 驗證指令：`python tools/dialogue_script.py`（模擬器 10/10、約 4 分鐘）

## 1. 反問（MISSING_SLOT）

| 項目 | 規則 |
|---|---|
| 觸發 | 缺關鍵資訊，例如「傳訊息」沒說對象 |
| 回應 | `ABSTAIN reason=missing_slot`，卡片問「要傳給誰？」 |
| 狀態 | 寫入 `files/followup_pending.tsv`（模板＋問題＋時間） |
| 有效期 | **5 分鐘**，過期自動忘 |
| 不觸發 | 資訊足夠時絕不反問（寧可做錯也不要一直問） |

## 2. 記住答案（Follow-up）

| 項目 | 規則 |
|---|---|
| 觸發 | 有未過期的缺口，且新指令「看起來像回答」 |
| 「像回答」的判準 | **≤ 8 字、且不含任何動作詞**（打開／傳／分享／調／搜尋…）；也接受「給小明」「傳給小明」這類帶前綴的回答（會正規化成「小明」） |
| 行為 | 把答案接回模板（`傳訊息給{slot}` → `傳訊息給小明`），再走一次完整管線 |
| 寧可錯哪邊 | **寧可把回答當新指令**（失敗，使用者重講），也不要把新指令當回答（做出沒要求的事） |

## 3. 取消（CANCELLED）

| 項目 | 規則 |
|---|---|
| 觸發 | 「取消」「不要」「不用」「算了」「停止」「別…」開頭 |
| 行為 | **什麼都不做**、清掉未完成的缺口、回「好，取消」 |
| 為什麼做寬 | 誤判成取消＝少做一件事；反向誤判＝使用者說不要卻照做 |

## 4. 再做一次（Repeat）

| 項目 | 規則 |
|---|---|
| 觸發 | 完全比對「再做一次／再來一次／重複／重做／再一次」 |
| 行為 | 讀 `files/last_command.txt`（**只存指令一行**）重跑 |
| 何時寫入 | 只在任務**成功**時寫；失敗不覆蓋 |
| 沒有紀錄時 | 誠實回「沒有上一次」 |

## 5. 糾正（Correction）

| 項目 | 規則 |
|---|---|
| 觸發 | 完全比對「不是這個／不是它／錯了／換一種方式」 |
| 行為 | 從**最後一筆收據**取出「最後一個後置條件成立的步驟」，把（效果 × 手段）**一次禁掉** |
| 範圍 | `global` scope —— 但效果鍵本身含目標（`NAVIGATE:app:日曆`），所以實際只影響這一件事 |
| 為什麼不用畫面指紋 | 糾正時規劃看的是**我們自己的畫面**；用畫面指紋當範圍，下一輪就對不上 |
| 還原 | App 內「🚫 反例」點一下刪除，立即恢復 |

## 交互作用（劇本驗證的順序）

```
打開設定        → SUCCESS
再做一次        → SUCCESS（重跑）
不是這個        → correction=applied（記下禁令）
打開設定        → ABSTAIN no_candidate（被自己擋住）
（刪除反例）     → 恢復
打開設定        → SUCCESS
傳訊息          → missing_slot（反問）
小明            → 回答接回原句 → sensitive_operation（安全閘門）
取消            → cancelled
打開設定        → SUCCESS（取消沒有污染狀態）
```

實測 **10/10**。

## 已知邊界

- 一次只有**一個**待回答缺口；同時缺兩個資訊時只問第一個。
- 回答支援「小明」「給小明」這類單一短語；「小明然後傳給他說晚安」這種複合句會被當新指令。
- 糾正只針對**最後一個成功步驟**；如果要糾正較早的步驟，目前得用反例頁手動刪。
- 這些狀態都在本機檔案，**不上傳**；刪 App 即清除。

## A. 真機一接上就能驗（不需要寫程式）

| 項目 | 怎麼驗 | 卡在哪 |
|---|---|---|
| R1–R8（`WAE_RealDevice_Checklist.md`） | `python tools/device_checklist.py -s <序號>` | 手機沒接 |
| A3 OCR 文字＋座標 | 開一個 WebView／Flutter 頁，看 `dryrun … ocr=N` 是否 >0 | 需真機 App |
| B5 語意相似（MiniLM） | `logcat WAE_MATCH` 看相似度分數是否合理 | 需真機＋真實別名 |
| I3 114 條評測 | `python tools/gen5_eval.py --install` | 需真機 |
| E6 音訊／媒體狀態 | 播放音樂後「暫停／播放」是否真的停 | 需真機有播放器 |

**這一組的價值**：全部都是「已寫好、只差驗」——真機接上後一小時內可以清掉五項。

## C. 刻意不做（附理由）

| 項目 | 理由 |
|---|---|
| A13 影片／遊戲畫布 | 只能手勢、不承諾理解畫布內容——承諾了就是騙人 |
| F8 風控／驗證碼辨識 | 一旦「辨識驗證碼」就會被用來繞過風控；**停手不硬闖**才是正確行為 |
| G9 約束可攜 UI | 格式已有，但匯出／匯入涉及隱私（別人的禁令清單），暂不做 UI |
| H4 喚醒詞 | 耗電與隱私成本高，先用「助理鍵／語音輸入」手動觸發即可 |

## 建議順序

1. **真機接上** → 清 A 組（R1–R8、A3、B5、I3、E6）
2. **B1**（可靠度四項）→ 用 `health.py` + 114 條回歸
3. **B2**（新能力）→ 每加一項就在 `gen5_suite4.tsv` 加案例
4. **B3**（大顆的）→ 一次一項，抽完／做完都跑 `health.py`

> 判準：**能讓「驗證過的次數」變多的先做**，能讓「版面變大」的先不做。

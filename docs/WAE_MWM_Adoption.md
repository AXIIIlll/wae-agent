# MWM 文件吸收清單：哪些進 Gen-5、哪些丟掉

> 日期：2026-11-17｜來源：`手機世界模型（MWM）計畫書 v1.0`
> 原則：**主線是 Gen-5；MWM 只取零件**。凡是要換產品定位、要上雲、要押訓練的，一律不取。

---

## 0. 一句話

MWM 值錢的不是「世界模型」，是**編譯／執行的分工、三通道驗證、版本戳、合約層**這四件事——它們全部可以在**不訓練任何模型**的前提下接進 Gen-5。

---

## 1. 「編譯器由誰擔任？」——三種角色分清楚

你的問題是「能不能讓我們自己的 AI 模型當編譯器」。答案：**能，但只能當「離線編譯器」，不能當 runtime。**

| 角色 | 誰來做 | 產出 | 為什麼 |
|---|---|---|---|
| **離線編譯器**（建置期） | **0.6B 模型＋人審** | 效果 DSL／巨集／別名表 | 它慢、會錯，但只跑一次；輸出是可讀的資料，錯了看得見 |
| **線上骨幹**（執行期） | 確定性核心（`Agent`） | 動作 | 必須毫秒級、可重現、可稽核 |
| **線上判斷**（分支時） | 校準器／反例庫／（未來）小模型 | 換路／棄權 | 只需要「要不要」「哪一條」，不需要生成 |

**三道閘（缺一不可）**：模型編出來的東西必須 ① 是 DSL／TSV，不是程式碼；② 過得了離線重放測試；③ 可一鍵回滾。

> 這就是 MWM「世界模型是編譯器，不是 runtime」的正確落地版本：把「世界模型」換成「我們的模型＋人的審核」，其他照抄。

## 3. 三個立刻可做的（成本低、回報高）

### 3.1 靜默失敗率（半天）

在 `Outcome` 增加一個明確狀態，並在 `Agent` 裡把「回報成功但後置條件不成立」單獨計數：

```
silent_failures / tasks
```

**這是全篇最該先拿的一項**：它不改行為，只改度量，卻直接回答「它有沒有騙我」。

### 3.2 三通道驗證（1–2 天）

無障礙服務已經在跑，只要在 `res/xml/wae_accessibility_service.xml` 的 `accessibilityEventTypes` 加上 `typeNotificationStateChanged`，就能拿到通知文字。

驗證規則：`後置條件成立` **或** `出現預期通知` → 才算真的成功。
簡訊（OTP／扣款）留給 B2B 場景，消費端不強求。

### 3.3 版本戳（半天）

`Frame` 已經有 `appVersion`；把它寫進**反例、轉移、收據**三處。之後任何一條紀錄都能回答：「這是哪一版 App 的經驗？」

## 4. 明確丟棄（不取，理由寫清楚）

| MWM 的主張 | 為什麼不取 |
|---|---|
| 45M 世界模型 ＋ 5 個 head | 現在解的還不是瓶頸；只留 4 週探針，不進主線（見 §5） |
| 雲端 Action Bus／雲端標註／雲端 GPU | 我們的產品是**物理上沒有 INTERNET 權限**，這條會殺掉核心承諾 |
| 主動探測隱狀態（開購物車、查餘額） | 消費者的真實帳號不能這樣探；改成被動推斷 |
| 不做消費者 App、轉 B2B 海外 | 這是換產品，不是換架構；要換請另外決策 |
| 像素渲染器／生成式世界模型 | 對 agent 無用，8GB 也不可能 |

---

## 5. 世界模型：留一個探針，不進主線

已經寫好的地基（`core/worldmodel`）：`Transition`、`RuleBaselinePredictor`、`WorldModelEvaluator`（66 個 core 測試綠）。

探針規則：
- 限時 **4 週**、**只用模擬器**、**不碰你的手機**
- 唯一的問題：模型能不能在**未見版本**上打敗規則 baseline 5pp
- 打不贏 → 只保留「異常偵測」用途，不進產品主線

---

## 6. 一句話

**MWM 的正確用法：把它當「驗證與度量的清單」，不是「訓練計畫」。**
先把靜默失敗率、三通道驗證、版本戳拿下來——這三件不需要任何模型，卻直接讓產品從「能動」變成「可信」。

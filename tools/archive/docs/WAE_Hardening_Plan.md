# WAE 全面加固計畫（Hardening Plan）

> 版本：v1.0（2026-11-15）
> 狀態：**計畫，尚未修改任何程式碼**
> 前提：單一開發者（你）＋ AI 協作；最終可選擇「個人工具」或「可交付產品」兩種定位
> 原則：每一項都要有「可重複的驗收方式」，不接受「看起來好了」

---

## 0. 一句話目標

把 WAE 從「我的手機能用的實驗品」變成「**別人的手機也不能壞**」：
- 換品牌、換 Android 版本、換頁面大小 → 仍能啟動與執行
- 語音誤動作 → 不可能造成不可逆損害
- 重裝／更新／權限被收回 → 使用者自己 2 步內能修好
- 每一次改動 → 有自動化回歸，而不是靠人眼截圖

---

## 1. 完成定義（Definition of Done）與量化門檻

| 指標 | 門檻 | 量測方式 |
|---|---|---|
| 冷啟動成功率（3 品牌 × 3 Android 版本） | 100% | CI 裝置矩陣，啟動到可輸入 ≤ 5 秒 |
| 16KB page size 啟動 | 100% | 16KB emulator / 實機，`readelf -l` 驗證 LOAD align ≥ 0x4000 |
| 語音指令成功率（真人、安靜） | ≥ 90%（20 句 × 3 次） | 自動化 E2E harness，判定 `taskResult=SUCCESS` |
| 語音指令成功率（真人、60dB 噪音） | ≥ 75% | 同上，加噪音播放 |
| 語音誤動作（非指令被執行） | < 1/1000 次 | 噪音＋電視聲連續 30 分鐘，統計 `execute` 次數 |
| 敏感操作攔截 | 100% 必須可見確認 | 金流/破壞性/發布類指令全數走確認關卡 |
| 可撤銷率 | 可逆操作 100% 提供 undo | 每個 intent 標記 reversible + undo |
| 端到端延遲（講完→開始動） | p50 ≤ 2.5 秒、p95 ≤ 5 秒 | instrumentation 量測 |
| 服務/角色失效後的恢復 | ≤ 2 步、≤ 30 秒 | 引導流程演練（重裝、關閉無障礙、移除角色各一次） |
| Crash-free | ≥ 99.5% sessions | 本地 crash log 統計（離線可用） |
| 回歸保護 | 每次 commit 跑完單元＋instrumentation＋E2E smoke | CI |

> 沒有達到以上門檻前，App 對外定位只能是「本人自用」。

## 2. 修復總表（議題 → 編號 → 階段 → 驗收）

### A. 致命級（Phase 0，先做）

| 編號 | 議題 | 修法摘要 | 驗收 |
|---|---|---|---|
| A1 | 只在一台手機驗證 | 建立 3 品牌 × 3 版本裝置矩陣（實機 + emulator），CI 跑啟動/權限/助理/無障礙 smoke | 矩陣全綠 |
| A2 | 16KB 裝置崩潰 | 換 16KB-aligned 原生庫（sherpa-onnx 或自建 Vosk）；`LOAD align=0x4000`；保留 4KB fallback | 16KB 機型可辨識 |
| A3 | 助理角色反咬 | 改為「明確同意才取代」；內建「還原 Google 助理」按鈕；首次啟動說明影響 | 使用者 2 步還原 |
| A4 | 無障礙服務會斷 | 服務存活偵測 + 一鍵修復 + 定期提醒；更新/重裝後引導；用 QS 磚/懸浮窗做備援入口 | 切斷後 30 秒內可恢復 |
| A5 | 噪音誤動作 | VAD 前置 + 置信度門檻 + 意圖白名單 + 敏感操作確認 + 首週安全模式 | 30 分鐘噪音 0 次誤執行 |
| A6 | 沒有真人語音驗證 | 錄音回放測試集（20 句 × 3 人 × 噪音），納入 CI；建立語音回歸分數 | 成功率門檻達標 |

### B. 體驗級（Phase 1–2）

| 編號 | 議題 | 修法摘要 | 驗收 |
|---|---|---|---|
| B1 | 沒有喚醒詞 | 兩階段：先做低成本入口（QS 磚、側鍵長按、耳機鍵、桌面小工具）；喚醒詞另案（前景服務＋KWS，需接受耗電與通知） | 入口可用性測試 |
| B2 | 每次開啟重載模型 | Model/Recognizer 移到 process 級單例＋前景常駐（可選）；啟動預熱 | 冷啟 ≤ 1.5 秒、熱啟 ≤ 300ms |
| B3 | 講完直接執行 | 預設「我聽到：<文字>，執行/取消」確認卡；常用指令可設「信任免確認」 | 誤執行率下降、無需重講 |
| B4 | 沒有 undo | 每個動作標記 reversible；執行後 5 秒內提供「復原」（BACK/回上頁/取消輸入） | 可逆操作 100% 有 undo |

| B7 | 沒有歷史/進度 | Session 記錄 + 助理面板極簡進度（目前步驟 / 取消）；完成後可重播指令 | 長任務可見進度 |
| B8 | 主畫面不好用 | 新手引導 3 步 + 常用指令建議 + 最近 3 筆（可關閉）；系統檢查移到首頁可見 | 首次使用 60 秒內講出第一句 |

## 3. 致命級詳案

### A1 多裝置矩陣

**根因**：只有 SM-A5560；無障礙樹、Assistant、語言包、頁面大小都因機型而異。

**做法**
1. 建立 `docs/COMPAT_MATRIX.md`：品牌 / Android 版本 / 頁面大小 / Assistant 行為 / 已知問題。
2. 測試環境：
   - 實機：Samsung（現有）＋ 1 台其他品牌（Pixel 或小米）
   - Emulator：API 34（4KB）、API 35（4KB）、API 36（16KB）
3. CI 跑 smoke：安裝 → 開 App → 系統檢查全綠 → 助理啟動 → 無障礙執行「打開設定」→ 判定 SUCCESS。
4. 失敗即記錄到矩陣，不允許「只有三星能過」。

**驗收**：3 種環境 smoke 全綠、矩陣表填滿。

---

### A2 16KB 頁面

**根因**：`libvosk.so`（0.3.47）LOAD 區段只對齊 4KB。

**選項（依序評估）**
1. 上游是否有 16KB-aligned 的 vosk-android 新版本 → 有就升級（最低成本）。
2. 自行 cross-compile Vosk + Kaldi，link flag `-Wl,-z,max-page-size=16384`（成本中高，時間 1–2 天）。
3. 改用 **sherpa-onnx**（k2-fsa，Apache-2.0，2024 後版本支援 16KB；需確認）→ 換 ASR 引擎（成本高，但順便解決模型可換）。
4. 最終 fallback：執行期偵測 `getconf PAGE_SIZE`（或嘗試載入失敗）→ 不載入 Vosk，改用系統辨識/打字，App 不死。

**驗收**
- `readelf -l lib*.so | grep LOAD` 全部 `Align 0x4000`。
- 16KB emulator 上：啟動、辨識、執行全通。
- 4KB 機型不受影響。

---

### A3 助理角色生命週期

**根因**：設為預設助理會 shutdown Google 語音服務；卸載重裝 role 消失；使用者不會還原。

**做法**
1. 首次引導明列後果：「會取代 Google 助理；可一鍵還原」。
2. 內建「還原 Google 助理」按鈕（`cmd role` 等價的 RoleManager 流程；若系統不允許，提供步驟圖）。
3. 每次啟動檢查 role；若遺失 → 系統檢查頁提示（P1 已有雛形，需擴充還原）。
4. 不主動自動搶 role；只有使用者按下才請求。
5. 若 Google 服務被停用，提供「重新啟用 Google App」引導。

**驗收**：一鍵還原成功、重裝後 2 步恢復。

---

### A4 無障礙服務韌性

**做法**
1. 服務存活偵測：定時（或 UI 進入時）檢查 `activeInstance`；死亡即提示。
2. 一鍵修復（已有系統檢查）：導向設定、顯示服務名稱、教使用者開。
3. 更新/重裝流程：App 啟動時偵測「版本變了但服務未綁定」→ 顯示引導。
4. 備援入口：QS 磚、懸浮窗、快捷方式（部分功能不依賴無障礙，例如只開 App）。
5. Watchdog：服務 `onServiceConnected`/`onDestroy` 記錄；崩潰自動重試綁定（需系統允許）。

**驗收**：手動關閉服務 → 開啟 App 30 秒內被偵測並可一鍵恢復。

---

### A5 語音安全（最重要）

**多層防線**
1. **前置 VAD**：沒有語音能量 → 不進辨識。
2. **置信度**：低於門檻 → 不自動執行，顯示「我聽到：…」讓使用者確認。
3. **意圖白名單 + 風險分級**：每種 intent 標記 `SAFE / NEEDS_CONFIRM / BLOCK`。
4. **敏感操作確認**：金流/破壞性/公開發布 → 必定跳出可見確認（語音不能單獨放行；可加 PIN）。
5. **安全模式**：安裝後前 7 天或前 20 次指令，所有語音指令都要確認；使用者可關。
6. **不可逆阻擋**：`IRREVERSIBLE` 標記的步驟，語音路徑直接 BLOCK。
7. **可撤銷**：可逆操作執行後提供 undo。
8. **噪音降級**：連續低信心 → 自動暫停語音，提示改打字。

**驗收**
- 噪音 30 分鐘：0 次執行。
- 敏感指令 10/10 跳出確認；無 PIN/確認則 0 次執行。
- 誤動作測試集（故意含「確定/關閉/傳送」的噪音）→ 0 次。

---

### A6 真人語音驗證

**測試集**
- 20 句（打開 App、搜尋、點按、輸入、返回、播放、傳訊息、導航…）
- 3 位說話者（含不同性別/語速；若只有你，至少 3 種語速與距離）
- 2 種環境（安靜、60dB 噪音）
- 每句 3 次 → 共 360 次辨識＋執行

**Harness**
- 手機端播放錄音 + 助理收音（喇叭→麥克風）或直接注入 WAV（目前 E2E hook 可擴充）。
- 自動收集：辨識文字、信心、`taskResult`、耗時。
- 產出報表：成功率、混淆字、失敗分類。

**驗收**：安靜 ≥ 90%、噪音 ≥ 75%、平均延遲 p50 ≤ 2.5 秒。

## 4. 體驗級詳案（摘要）

- **B1 入口**：短期先做「不用長按」的三個入口（QS 磚已存在、桌面小工具、耳機/側鍵映射視機型）。喚醒詞列 Phase 3 另案，先寫規格（KWS 模型、前景服務、耗電/通知、隱私）。
- **B2 模型常駐**：把 `Model`/`Recognizer` 提升到 `Application`/前景服務層級；助理只做 UI；量測冷啟/熱啟。
- **B3 確認卡**：預設顯示「我聽到：X」＋「執行/取消」；常用白名單可免確認（設定裡）。
- **B4 undo**：Intent 標記 `reversible` + 反向動作（BACK、清除輸入、回主頁）；5 秒 undo 視窗。
- **B5 覆蓋**：用 `ui_task_templates.tsv` 擴充；搜尋類加前置 LAUNCH_APP；建立 benchmark 迴歸。
- **B6 去重**：分解後合併相同 package 的 LAUNCH_APP；避免重複步驟。
- **B7 進度**：Session store + 助理面板一行進度；完成/失敗 toast 級提示（不破壞極簡）。
- **B8 引導**：首頁 3 步引導（無障礙→助理→講第一句）；常用指令 chips；系統檢查首頁可見。

## 5. 語音層詳案（摘要）

- 模型策略（C1/C6）：內建 base（42MB），支援本機匯入 plus；設定頁顯示模型/授權/大小。
- 繁簡（C2）：換完整 OpenCC s2t 表（約 1–2MB）或建立覆蓋率檢查；CI 驗證「簡體輸入→繁體輸出」100%。
- 句尾（C3）：VAD + endpoint 雙條件；可調 `silence_ms`；最長句 15 秒。
- 信心（C5）：Vosk `setWords(true)` 取平均信心；<0.6 → 確認模式。
- 模型授權：Vosk Apache-2.0、模型 Apache-2.0；sherpa-onnx Apache-2.0；全部記錄在 `docs/LICENSES.md`。

## 6. 安全與隱私詳案

- D1 敏感頁面：用 TSV 定義敏感 package（銀行/支付/密碼管理器）；進入時不記錄文字、截圖禁用、欄位遮罩。
- D2 語音確認：見 A5；加上「強制 PIN」選項。
- D3 log：建立 `WaeLog`（release 只留事件碼，不留文字）；debug 用 build flag。
- D4 金鑰：移出 repo；CI secret；重新產生 release key；舊 APK 作廢重簽。
- D5 文件：README 說明「資料在 APK 內、可反編譯」，不宣稱加密。

## 7. 工程重構（摘要）

- E1 三層架構：
  - `runtime/`：無障礙服務、管線、意圖、安全閘門
  - `session/`：任務狀態、歷史、undo、checkpoint
  - `ui/`：共用設計元件（波浪、卡片、輸入列）＋助理/懸浮窗/主畫面
- E2 旗標：每個 flag 有 kill switch、A/B 指標、回滾步驟；順序 TASK_OS → GROUNDING_2 → OMEGA。
- E3/E4 測試與 CI：unit（現有 84 檔）＋ instrumentation（服務/權限/角色）＋ E2E（語音回放）＋ benchmark；CI 一鍵。
- E5 版本：SemVer、CHANGELOG、保留上一版 APK。
- E6 體積：AAB、asset 審查（未使用 TSV 移出）、模型可選。
- E7 AI 防護：golden tests（固定輸入→固定輸出）、截圖 diff、每次改動跑 E2E smoke、變更清單。

## 8. 合規與營運

- F1 政策自評表（無障礙用途、助理替換、資料處理）；必要時改 F-Droid/自架/側載。
- F2 相容清單：Samsung/Pixel/小米 + Android 14/15/16 + 4KB/16KB。

## 10. 風險與止損線

**只能緩解、不可能完全修的**
1. OEM 對 Assistant/無障礙的行為（只能矩陣測試＋降級）
2. Play 政策解釋權（只能自評＋必要時不上架）
3. 自動化第三方 App 的絕對安全（只能多層防線＋不可逆阻擋）
4. 離線模型的天花板（只能換模型分級）

**止損線（達到就改變定位，不硬撐）**
- 若 16KB 在 2 天內找不到可維護方案 → 接受「僅支援 4KB 機型」並在文件明示，不再投入產品化。
- 若真人語音成功率 < 70% → 暫停語音功能，保留打字/無障礙，重新評估模型。
- 若多裝置 smoke 無法穩定 → 定位為個人工具，不追求上架。
- 若安全確認/undo 做不完 → **絕不對外發布**（這是紅線）。

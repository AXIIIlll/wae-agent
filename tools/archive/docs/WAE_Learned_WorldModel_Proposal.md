# WAE 學習式世界模型架構提案（World Model + HER + 自監督表徵）

> 狀態：**構想階段，尚未實作**。這份文件只記錄設計與評估，不改動現有程式。
> 提出者：使用者（2026-11）／整理與技術評估：AI 協作者
> 關聯文件：`docs/WAE_Extreme_Architecture.md`（現行純程式架構）

---

## 1. 原始構想（使用者的話）

> 訓練 AI 模型時，直接給它一個**模擬機**，再給它一個**目標**，讓它自己亂點直到達成目標；
> 達成目標就給獎勵。完全不教它規則，純讓它自己摸索（類似 JEPA 的加強版）。

三個已知陷阱與解法：

| 陷阱 | 解法 |
|---|---|
| **獎勵太稀疏**（大海撈針，AI 撞不到目標） | **HER（Hindsight Experience Replay）**：亂點卻打開藍牙，就把這次目標改寫成「打開藍牙」並給獎勵 → 每次亂點都能學到技能樹 |
| **表徵崩塌**（把所有畫面壓成同一個向量，預測誤差永遠 0） | **對比學習 / VICReg 變異數正則化**：強制不同畫面 → 不同向量 |
| **真機試錯太慢** | 先從歷史雜亂影片建立**世界模型**，在「想像（Imagination）」裡以每秒數萬次速度做百萬次試錯，練出直覺後再上真機（Dyna 式） |

---

## 2. 這在文獻上對應到什麼（不是空想）

| 構想元素 | 對應的成熟方法 |
|---|---|
| 在想像中訓練 | **DreamerV1/V2/V3**（latent world model + imagination RL）、**MuZero**（learned model + planning） |
| 目標條件 + 事後回放 | **Goal-Conditioned RL + HER**（Andrychowicz et al. 2017）、GCSL（goal-conditioned supervised learning） |
| 防表徵崩塌 | **SimCLR / BYOL 對比學習**、**VICReg**（variance-invariance-covariance regularization）、**JEPA / I-JEPA**（LeCun） |
| 從影片學世界模型 | **Dreamer 的 offline pretraining**、**TD-MPC2**、**Genie / GAIA-1**（影片生成式世界模型） |

**結論：方向正確，是 2023–2026 的主流研究路線。** 真正的難點不在「想法」，在工程與資料。

---

## 3. 與我們現有架構的協同（這是最有價值的地方）

我們不是從零開始，現有程式已經有這個架構缺的三塊拼圖：

| 提案需要 | 現有程式 | 協同方式 |
|---|---|---|
| **獎勵訊號（目標是否達成）** | `core/goal/GoalCompiler.kt` + `PostCondition` DSL | **後置條件就是 reward oracle**：`SPINE_CHANGED / TEXT_PRESENT / VALUE_INC / TOGGLE_STATE / PKG_EQ` 可直接當 reward＝1，不需要人工標註 |
| **世界模型（狀態轉移）** | `core/automaton/`（狀態圖 + Beta 統計） | 現有圖是**表格型世界模型**；可先在此做想像 rollout（微秒級），再升級成 latent model |
| **訓練資料** | `core/twin/`（Twin 軌跡，含 before/after 簽名、動作、結果） | 每一筆成功軌跡 = 一條 (s, a, s', reward) 樣本，可直接餵 HER |
| **安全護欄** | `SafetyTypeSystem`、`ExplorationGuard`、`ActionContract` | 學習層永遠在 deterministic 層之下；RL 不能繞過禁區 |
| **HER 的 relabeling** | 上述 PostCondition | 「亂點到某個狀態」→ 推導出「實際達成了什麼條件」→ 自動 relabel，天然契合 |

> 換句話說：**我們已經有 reward 與 transition 的雛形，缺的是「學習型表徵 + 想像訓練 + 策略網路」。**

## 4. 建議架構（三層，不是端到端）

```
┌─ L3 真機執行層（現有，deterministic）───────────────────────────┐
│  安全型別 → 規劃/策略 → 動作契約 → 後置條件驗證 → 負邊          │
│  （學習層只能「建議」，不能繞過這一層）                          │
└──────────────────────────────────────────────────────────────┘
              ▲ 建議動作分數 / 目標分數
┌─ L2 學習層（新增）──────────────────────────────────────────────┐
│  表徵編碼器 E：畫面（簽名/文字/元件能力/截圖特徵）→ z            │
│  世界模型 f： (z, a) → z'  +  不確定度 σ                          │
│  策略 π： (z, goal) → a 分數                                     │
│  訓練：在「圖/Latent 想像」中 rollout + HER + VICReg              │
└──────────────────────────────────────────────────────────────┘
              ▲ 離線資料
┌─ L1 離線建置層（PC／GPU）────────────────────────────────────────┐
│  1. 收集：Twin 軌跡 + 使用者授權的螢幕錄影 + 自動探索軌跡        │
│  2. 預訓練：對比學習（同一頁不同時刻 = 正樣本）                  │
│  3. 世界模型訓練：預測 z'／後置條件成立機率                       │
│  4. 策略訓練：HER + 圖上 rollout（百萬次）                        │
│  5. 匯出 ONNX（INT8）→ 手機端只做推論                             │
└──────────────────────────────────────────────────────────────┘
```

**關鍵決策：手機端只做「推論」，不訓練。** 訓練在 PC/GPU 完成，匯出 ONNX（我們已有 ORT Android 1.22 與 INT8 流程）。

---

## 5. 三個陷阱在我們系統中的具體解法

### 5.1 稀疏獎勵 → HER（但我們更容易）

- 現有 `PostCondition` 可從**任意成功轉移**推導「達成了什麼」，relabel 成本近乎 0
- 目標空間不是自然語言，而是**結構化條件**（`TOGGLE_STATE(藍牙,OFF)`），所以 HER 的 relabel 是精確的，不是啟發式
- 額外優勢：負邊（NegativeEdgeStore）可直接當**負獎勵**，避免重複撞牆

### 5.2 表徵崩塌 → 對比 + VICReg

- 正樣本定義：**同一頁面**的不同時刻（簽名相似度 ≥ 0.9）
- 負樣本：不同頁面（簽名相似度 < 0.5）
- 加上 VICReg 的 variance/covariance 項防止塌縮
- 量測：**有效秩（effective rank）**與**正負樣本距離比**，低於門檻就報警

### 5.3 真機太慢 → 先圖上想像，再上 Latent 想像

分兩階段，不必一開始就做影片級世界模型：

| 階段 | 想像介質 | 速度 | 風險 |
|---|---|---|---|
| **A（可先做）** | 現有**狀態圖**（表格） | 微秒/步 | 低（圖是實測來的） |
| **B（進階）** | Latent world model（學到的） | 毫秒/步 | 中（模型誤差會累積） |

> 建議：**先做 A**，用圖上 rollout 訓練策略（此時策略只是「圖上的啟發式學習」），
> 驗證有收益後再升級到 B。這樣即使 B 失敗，A 的成果仍然可用。

## 6. 誠實的風險與成本

| 風險 | 說明 | 緩解 |
|---|---|---|
| **樣本量不足** | 我們目前沒有大規模軌跡（真實使用資料幾乎為零） | 先用**自動探索**（S5，已實作護欄與 Bandit）產生資料；或用公開 UI 資料集預訓練 |
| **世界模型誤差累積** | 想像越長越不準 | 短 horizon（3–5 步）+ 每步用後置條件校正 |
| **手機算力** | 端上模型不能大 | 只推論、INT8、<10MB、<20ms/步 |
| **安全** | RL 策略可能學會危險動作 | deterministic 層硬阻擋（禁區＋安全型別＋契約） |
| **可解釋性下降** | 從「可列舉原因」變成「模型覺得」 | 保留雙軌：學習層只給**分數**，最終決策仍由可驗證規則產生 |
| **工程成本** | 訓練基礎設施、資料管線、評測 | 分階段，先 A 後 B |

**不建議做的**：端到端像素 → 動作的 RL（樣本效率太差、不可審計、手機端不可行）。

---

## 7. 分階段里程碑（建議）

| 階段 | 內容 | 驗收 |
|---|---|---|
| **W1** | 資料管線：Twin 軌跡 → (s, a, s', reward) + HER relabel | 可產出 ≥ 10 萬筆樣本 |
| **W2** | 表徵學習：對比 + VICReg | 有效秩 > 門檻；同頁/不同頁距離比 > 2 |
| **W3** | 圖上想像 + 策略訓練（表格世界模型） | 在 100 題基準上優於現行決策 ≥ 5pt |
| **W4** | Latent world model（取代表格） | 想像 rollout 與真機一致率 ≥ 85% |
| **W5** | 真機 A/B | EASY/MEDIUM 不掉、HARD 提升 |

## 10. 我的一句話評估

> 這個方向**是對的，而且我們現有的後置條件與狀態圖讓它比一般專案更容易落地**；
> 但一定要「混合」而不是「取代」——學習層負責泛化與直覺，deterministic 層負責安全與可驗證。
> 建議先做 **W1→W2→W3（表格想像）**，這三步不需要大量硬體、風險低、且每一步都有可量測收益。

# 附錄 A：好奇心驅動探索（無資料、無目標）的評估

> 使用者追加構想（2026-11）：
> 「給它一個雲端模擬機，讓它自己發覺手機的使用功能；不給任何訓練資料、盡量不給目標，
> 看能不能靠**好奇心**自己學會手機怎麼用。」

## A.1 這件事在文獻上叫什麼

| 概念 | 代表方法 |
|---|---|
| 內在獎勵（好奇心） | **ICM**（Intrinsic Curiosity Module, Pathak 2017）、**RND**（Random Network Distillation, Burda 2018） |
| 學習進度（competence） | **Learning Progress**、**Empowerment**（Klyubin 2005） |
| 無目標的技能發現 | **DIAYN**（Diversity is All You Need）、**APT**（Active Pretraining） |
| 硬探索的突破 | RND + PPO 在 Montezuma's Revenge 上首次超越人類（2018） |

**結論：這條路存在，但有一個關鍵前提——環境的「新穎度」必須可被有效估計，且樣本量要夠。**

## A.2 在手機 UI 上，為什麼比 Atari 更容易也更容易失敗

**更容易**：
- 手機 UI 是**符號化**的（無障礙樹有 class / text / id / 能力），不需要從像素學「什麼是新事物」
- 新穎度可以直接定義在**結構化狀態**上：新狀態、新轉移、新元素類型、新頁面骨架
- 我們的 `automaton` 已經在統計「新狀態/新邊」——這本身就是最樸素的 novelty

**更容易失敗**：
- 動作空間大（每個畫面 20–40 個候選），隨機亂點的資訊增益很低
- 很多「新頁面」其實是**同一個頁面的不同內容**（列表滾動），novelty 會迅速飽和
- 沒有目標時，策略容易學會**退化解**（一直捲動、反覆開關同一個設定）
- 純好奇心不會自己學會「訂票」這種長程任務——它只會學會「探索」

## A.3 建議的好奇心設計（不是純隨機）

```
intrinsic_reward = w1 · state_novelty(z)          # RND：隨機網路對錶徵的預測誤差
                 + w2 · learning_progress          # 同一狀態下成功率上升 → 加分
                 + w3 · empowerment                # 動作對狀態的控制力（可預測性）
                 − w4 · repetition_penalty         # 重複同一動作 → 扣分
```

其中 `z` 用**符號表徵**（class/id/能力/文字統計的嵌入），不是像素。
另外用**資訊增益**（新邊數量）當輔助，讓探索有方向。

## A.4 結論：可以做，但建議「好奇心 → 目標條件」兩段式

| 階段 | 內容 | 產出 |
|---|---|---|
| C1 好奇心預訓練 | 符號環境中探索，最大化新狀態/新轉移 | 探索策略 + 表徵 |
| C2 目標條件微調 | 加入 `PostCondition` 當目標，HER relabel | 任務策略 |
| C3 產品化 | 只保留推論，安全層照舊 | 實際可用的 Agent |

> 只做 C1：會得到「很會亂逛的 Agent」，但不會完成任務。
> 只做 C2（沒有 C1）：樣本效率差（就是目前獎勵稀疏的問題）。
> **兩段式才有意義。**

# 附錄 B：雲端與模擬器的可行性（Colab 夠不夠？）

## B.1 Colab 能做什麼、不能做什麼

| 用途 | Colab 可行？ | 說明 |
|---|---|---|
| **訓練小模型**（表徵、世界模型、策略） | ✅ 可以 | 免費 T4 16GB 足夠跑 10–50M 參數量級；Pro 有 L4/A100 |
| 長時間訓練（>12h） | ⚠️ 勉強 | 免費版 session 會斷、需 checkpoint 到 Google Drive；Pro 較長但仍非 24/7 |
| 大規模平行 rollout | ❌ 不適合 | 沒有 GPU 加速的環境模擬，rollout 在 CPU 上很慢 |
| **跑 Android 模擬器** | ❌ **不可行** | Colab VM **沒有 KVM**（`/dev/kvm` 不存在），x86 硬體加速不可用；純軟體模擬慢到無法用 |
| 儲存資料集 | ⚠️ | 需掛 Google Drive，容量與 I/O 都受限 |

**結論：Colab 適合「拿來訓練」，不適合「拿來當模擬器」。**

## B.2 模擬器要放哪裡（由快到慢）

| 方案 | 速度 | 成本 | 備註 |
|---|---|---|---|
| **本機 PC + Android 模擬器**（WHPX/Hyper-V 加速） | 最快（1–5 步/秒 a11y 層） | 免費 | 需要 CPU 虛擬化；你已有 Android SDK |
| 雲端 VM 開巢狀虛擬化（GCP `--enable-nested-virtualization`） | 快 | 中（每小時計費） | 可與 GPU 同機 |
| 雲端真機農場（Firebase Test Lab / AWS Device Farm / Genymotion SaaS） | 中 | 貴 | API 型、適合驗收不適合大量 rollout |
| Colab 跑模擬器 | ❌ | — | 無 KVM，不可行 |
| **自建符號模擬器**（用 automaton 圖） | **極快（萬步/秒）** | 免費 | 抽掉像素，只保留狀態/動作/轉移 |

## B.3 建議：三種環境並用

1. **符號模擬器**（自己寫，用現有狀態圖）：做 C1 好奇心預訓練，CPU 即可，Colab 也能跑
2. **本機 Android 模擬器**：做 C2 驗證與少量真實 rollout
3. **真機**：最後驗收，只在安全護欄下

Colab 的角色：**訓練表徵／世界模型／策略**（資料從符號模擬器與本機模擬器產生，放 Drive）。

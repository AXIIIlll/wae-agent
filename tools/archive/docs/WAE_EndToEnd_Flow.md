# WAE 端到端架構：從一句指令到動作結束

> 只描述「指令進來 → 動作結束」的完整流程與所有分支；不含 UI 細節、模型訓練、資料表簡化。
> 圖中標記：`[既有]` 已實作、`[新]` 本輪規劃要加、`[旗標]` 由 ExtremeRuntimeHooks 控制、`[失敗]` 失敗分支。

## 1. 三條執行路徑的差別（路由依據）

| 路由 | 判定 | 優點 | 缺點/風險 |
|---|---|---|---|
| 快速路徑（舊管線） | 明確動詞 + 單一對象（開/關/設定值） | 毫秒級、可預測 | 不擅長開放目標 |
| 序列拆解（舊管線） | 明確多步（先A再B） | 快 | 步驟多時脆弱 |
| Agent（LLM） | 開放式/目標性語句 | 能應對未知 App/畫面 | 慢、需模型、0.6B 能力有限 |
| 直接確認/拒絕 | 高風險意圖 | 安全 | 需使用者互動 |

**注意**：目前實作仍是「文字長度 ≥6 → Agent」，本輪要改成上表的路由規則。

---

## 2. 所有「結束狀態」定義

| 狀態 | 意義 | 觸發 |
|---|---|---|
| `SUCCESS` | 所有 goal / step 通過嚴格驗證 | 正常完成 |
| `FAIL` | 某 goal/step 無法完成（含安全攔截） | 重試/恢復用盡 |
| `NEED_USER` | 需要澄清/輸入 | 歧義、需要變數、畫面無法判斷（截圖失敗） |
| `CANCELLED` | 使用者停止 | 停止鈕、語音取消、返回 |
| `TIMEOUT` | 逾時 | 全域/單步逾時 |
| `REJECTED` | 前置閘門/安全直接拒絕 | VoiceRiskPolicy BLOCK、PolicyVerifier |

## 3. 邊界情況清單（全部要有明確行為）

### 3.1 入口層
- 語音是噪音/太短 → 丟棄，不執行（VoiceCommandGate）
- ASR 誤認 → 修正表；修正後仍低信心 → 詢問
- 文字為空/只有空白 → 不執行
- debug_command / agent_goal 檔 → 讀後刪除，走同一管線
- 使用者連按/重複指令 → 任務串行化（busy → 拒絕或排隊）

### 3.2 前置層
- 無障礙服務未開/被系統殺 → 提示 + 深連結到設定
- 助理角色未設 → 提示
- 麥克風未授權（語音）→ 提示
- 前景是 WAE 自己 → 拒絕操作自身
- 螢幕鎖定/黑屏 → 提示解鎖
- 已有任務在跑 → busy 處理（停止/排隊）

### 3.3 路由/規劃層
- 模型未載入/載入失敗（FD 失敗）→ fallback 舊管線
- 模型輸出非 JSON / 被截斷 → PlanParser 容錯；仍失敗 → fallback/告知
- 計畫步驟 > 上限 → 截斷或改問
- 計畫包含付款/刪除 → 安全拒絕（prompt 已禁止，仍要後端擋）
- App 不存在（目標 App 未安裝）→ 反問/建議相近 App
- 目標 App 名稱歧義（多個相似）→ 問使用者

### 3.4 App 選擇（新）
- 無候選 → 反問使用者
- 候選開啟後不像影劇 App → BACK 換下一個（≤3）
- 全部不像 → 反問
- App 開啟後停在播放器/廣告/登入頁 → BACK 退出再試
- 截圖判斷失敗（OCR/模型無結論）→ 反問

### 3.5 感知層
- 畫面白屏/載入中 → 等待（動態 UI 閘門，不硬點）
- 廣告/權限彈窗 → L2 去彈窗
- IME 鍵盤遮擋 → 收鍵盤/等待
- 多視窗/分割畫面 → 取焦點視窗；前景 package 漂移只警告
- 畫面無 a11y 節點（Canvas/影片 App）→ OCR/圖示偵測；仍無 → 截圖判斷或反問
- 頁面姿態誤判（例如 Maps 首頁被當搜尋結果）→ 不採「自動回首頁」規則

### 3.6 決策層
- 歧義（多個同分）→ ASK_USER 或 AUTO_RESOLVE（依策略）
- TYPE 找不到輸入框 → NO_INPUT_ENTRY → BACK（≤2）→ 仍無 → 換路徑/反問
- 目標是入口但不是輸入框 → 入口階梯（先 TAP）
- 開關已開/已關 → 不動作，直接成功
- 滑桿找不到 → 上下掃描；仍無 → 失敗（不硬拉）
- 目標是唯讀元素（進度條/純文字）→ 拒絕（READ_ONLY_SENSITIVE）
- 底部導航頁籤同名 → 排除
- 重複動作（同 selector 短時間內）→ 冪等略過

### 3.7 安全層
- BLOCK（付款/轉帳/刪除敏感資料）→ 拒絕並說明
- CONFIRM（敏感但可逆/需確認）→ 確認卡/語音確認
- 風控字樣（驗證碼/OTP）→ SecurityGuardrails 攔截
- 不可逆動作 → 永遠確認
- 密碼/驗證碼欄位 → 不自動填

### 3.8 動作層
- 目標節點消失（TOCTOU）→ 不下發，重感知
- 點擊座標失效/元素滑出畫面 → 重感知/捲動
- 輸入中文失敗/鍵盤未開 → 重試/換 IME 方式
- SUBMIT 重複提交 → 冪等/去重
- 需要 SYSTEM 返回但前景已變 → 重新判斷

### 3.9 驗證層
- 動作已發但畫面沒變（TAP 無效）→ 重試 + 恢復
- 驗證通過但實際是誤判（例如 title 相同）→ 嚴格規則：TYPE 文字、OPEN_APP package、toggle checkable
- UNCERTAIN → 不算成功、不寫記憶，最多重試一次再判定

### 3.10 中斷/停止
- 使用者按停止 → 下一檢查點安全停止（不半途亂點）
- 語音取消 → 同上
- 逾時 → 停止並回報
- 服務斷線 → 中止並提示
- 來電/通知打斷 → 恢復感知後重新判斷

### 3.11 收尾
- 成功 → 寫 SessionHistory、更新記憶（嚴格成功）
- 失敗 → 保留原因、記錄 diagnostics
- 取消/逾時 → 清理暫存（避免下次誤用）
- 重規劃上限（Agent ≤2、舊管線 ≤2 次）→ 用盡即停，不無限重試

## 4. 資料與介面（各層吃什麼）

## 5. 要在圖上補的三個洞（本輪新功能的位置）

1. **E3 Intent Router**（取代「長度 ≥6」分流）
2. **E4c ① App 選擇**（意圖→候選→開啟驗證→換候選→反問）
3. **E7 記憶倉庫 + 背景只讀探索**（讀寫規則如上）

這三個加完，流程就是：
**指令 → 閘門 → 路由 → （選 App）→ 規劃 → 感知/決策 → 安全 → 動作 → 驗證 → 記憶 → 回饋**
